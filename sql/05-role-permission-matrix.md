# 融销通 - 用户角色权限矩阵

## 三种角色

| role 值 | 角色名 | 说明 |
|---|---|---|
| 1 | 🌾 普通用户（农民） | 同时是商品发布者和购买者 |
| 2 | 👨‍🌾 专家 | 需注册后经管理员审核通过才解锁全部专家功能 |
| 3 | 👑 管理员 | 后台管理者，不开放自助注册 |

## 特殊规则说明

### 规则 1：专家审核状态影响权限

专家角色（role=2）注册后默认 `expert.audit_status=0`（待审核），审核**通过前**：
- ✅ 可以浏览专家列表（但自己不会出现在列表里）
- ❌ 不能使用专家专属功能：`/api/appointment/my/expert`、回答问题时不会自动标记 `is_expert=1`、`/api/expert/profile` 不能修改
- 管理员审核通过后 `audit_status=1` 才解锁全部专家功能

### 规则 2：农民同时是买家和卖家

role=1 的用户可以：
- 发布商品 → 在订单里作为 **seller_id**（卖家视角，`GET /api/order/sale`）
- 购买别人的商品 → 在订单里作为 **buyer_id**（买家视角，`GET /api/order/purchase`）
- 订单相关接口通过查询参数/路径区分是买家还是卖家视角

### 规则 3：管理员不能自助注册

管理员账号通过后端 SQL 初始化（admin/123456），或在数据库里手动插入 user 表 role=3 的记录。注册接口 `POST /api/auth/register` 不接受 role=3 的注册请求。

### 规则 4：知识文章只有专家和管理员能发布

普通用户（role=1）浏览知识、点赞，但不能发布。发布接口 POST `/api/knowledge` 会校验 `role IN (2, 3)`。

### 规则 5：融资只有农民能发起

融资相关接口（除了管理员审核）仅限 role=1 农民角色使用，专家和管理员前端不会展示融资申请入口。

## 后端实现方式建议

```
Controller 方法上用 Spring Security 的 @PreAuthorize 注解标记需要的角色：
- 只有农民能调用的：@PreAuthorize("hasRole('FARMER')")
- 专家或管理员：@PreAuthorize("hasAnyRole('EXPERT', 'ADMIN')")
- 仅管理员：@PreAuthorize("hasRole('ADMIN')")

Spring Security 统一处理：
JwtAuthenticationFilter 解析 token -> 拿到 userId -> 查 user 表 -> 构建 LoginUser -> set 到 SecurityContext
然后检查 @PreAuthorize 注解 -> 对比 LoginUser 的 authorities -> 不匹配则返回 403
```
